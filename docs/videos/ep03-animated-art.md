- **Reality-check corrections applied 2026-07-14** (verified against source; the old outline had stale claims):
  - **Stride/Skip still exist, in the web editor** (`Editor.tsx` `FrameTimeline`, buttons literally read `Stride` / `Skip`). Only the old `/loominary` chat command was removed. Exact behavior: Stride keeps every n-th frame and **accumulates** removed delays; Skip drops every n-th and **merges** delay into the neighbor. The cue states this precisely.
  - **The frame codec is automatic, not a picker.** Lossless AV1 (`FLAG_AV1`) is chosen only when smaller than raw+zstd; lossy (`FLAG_AV1_LOSSY`) is the only manual choice, via the **"⚡ Lossy animation — much smaller"** checkbox on the export page. The export page's "Codec" selector is the storage *channel* (carpet/shade/banners), not the frame codec, don't conflate them.
  - **Delta / sparse frame modes are decode-only legacy** (`MapBannerDecoder.extractFrames` still reads them; `encode.ts` never emits them). Web exports are **raw-or-AV1 only**. Do not claim the editor "chooses between raw, delta, sparse, and AV1."
  - **There is no per-frame byte budget** shown anywhere, budget is strictly **per tile**. The frame-budget card contrasts one raw frame (16,384 B) with one tile's compressed capacity (up to 15,482 B); it is a rhetorical contrast, not a UI readout.
  - **"Sixty frames"** is illustrative rhetoric, not a constant. (60 happens to be both the default Quality value and the export's heavy-animation threshold, but nothing guarantees "60 frames fit.") Keep it framed as an example.
  - The **DECODING bar is real**: `PlaceholderArt.decoding()` draws "DECODING" + a green fill bar + "%" into the 128×128 map; driven by `MapBannerDecoder` repainting every ~5%.
  - **Wall-clock sync is real**: `AnimatedMapState` advances on `System.currentTimeMillis()` on the **render thread** (registered on `WorldRenderEvents.END`), deliberately, so frame delays shorter than one game tick (50 ms) are honoured; a tick-driven animation would be capped at 20 fps and fast GIFs would crawl. The same absolute-time basis is what keeps every viewer on the same frame. Multi-tile grids are grouped by `syncKey` (`cols:rows:frameCount:author:title`) and advance as one, so the "tiles stay in sync" tail is accurate.
  - **Composite single-stream (`FLAG_AV1_COMPOSITE`) is multi-tile only** and is **not mentioned** here, it's ep04 territory. The multi-tile sync tail relies on the sync grouping above, not on composite encoding.
- **Import info box** (verbatim, if shown on camera): "Animated GIFs only preview the first frame here. When you proceed, every frame will be quantized — large GIFs with many frames may take a moment to process."
